# MUS Booking

MUS Booking 替音乐学院的同学预定琴房。学校的场地系统每天 21:00 开放第二天的预定，名额常常在几秒内被订完。同学在手机上排好想要的时段，服务器每晚 21:00 准时替每个人提交，结果第二天打开页面就能看到。

服务跑在一台服务器上，几位同学各自用邀请码绑定自己的学校账号，之后从手机浏览器免登录使用。

## 用起来是什么样

首页列出未来 7 天，每天一行。点空着的日子即可为那一天添加预定，选好起止时间和琴房，需要的话打开“每周重复”。一条预定可以很长，比如下午 13:00 到 19:00；学校规定单次最长 2 小时，提交时会自动切成几段，每段单独提交、单独显示结果。

每周重复的预定可以跳过某一次，也可以整体暂停，二者都能恢复。已经开放的日子（当天，或 21:00 以后的第二天）添加之后立即提交，不必等到晚上。

管理页列出成员、邀请码和每晚的结果，只有用管理账号登录过的浏览器才能看到；管理账号就在普通的登录页上登录。

## 每晚 21:00 发生的事

20:55 服务为第二天有预定的同学登录学校系统，20:59:30 重读日历页并为每一段取好预定表单。21:00 整，每个人的各段按时间先后依次提交，段与段之间隔 1 秒，不同的人同时进行。学校在开放前一刻会答复“尚未开放”，服务就每秒重试一次；某一段已被别人订走则记为失败，不影响其余各段。

提交之前，这一次会先记成“排队中”，之后用户的修改只影响以后的日子。服务即使在提交途中重启，也会接着把排队的段交完；已经发出却没收到答复的段，会去学校的“我的预定”里核对，绝不重复提交。

学校密码和登录凭据加密后存进数据库，密钥放在数据库之外的单独文件里。

## 在本机试用

需要 [uv](https://docs.astral.sh/uv/)。

```sh
uv sync
uv run mus-booking preview
```

预览命令用一个进程内的假学校系统和一份示例数据启动整个服务，并打印几个链接：成员首页、管理页，以及一个可以用来体验绑定流程的邀请链接。假学校系统按真实系统的规则答复，所以在预览里添加的预定也会真的“提交”并显示结果。

## 开发

```sh
uv run pytest
uv run ruff check
uv run ruff format
```

测试不访问网络。学校页面的解析用 `tests/portal/samples/` 里脱敏的真实页面片段核对，每晚的流程用虚拟时钟和假学校系统完整地跑一遍。

```
src/mus_booking/
├─ domain/    时段、琴房、预定与排程的规则，只做计算
├─ portal/    学校系统：登录链路、读取可预定内容、表单、提交；fake.py 是假学校系统
├─ store/     SQLite 数据库与密码的加密
├─ engine/    每晚的编排与随时的补交
├─ web/       页面、模板、样式与字体
├─ cli.py     命令行入口
└─ preview.py 预览用的示例数据
deploy/       systemd 单元、配置样例与 Caddy 配置片段
tools/        字体子集的生成脚本，以及学校系统的探测脚本
```

页面用的思源宋体和 Fira Code 是按需切好的子集，放在 `web/static/fonts/`；改了页面文字之后，用 `tools/build_fonts.py` 重新生成，用法见脚本开头。
